# 技术与保存决定

## 2026-11-10：代码和交接记录一起保存

- 在云环境开发，以现有 Git 仓库保存代码与记录，通过推送保存到远端。
- README 记录启动方式，HANDOFF 记录当前进度，AGENTS 约定后续交接方式。
- 邮件仅可作为用户自行保存摘要的补充，不作为代码或环境恢复的唯一来源。
- 不假设云实例、运行中的进程或聊天上下文永久保留。

## 2026-11-10：提供可验证的离线副本

- 使用 Git bundle 保存所有本地分支/标签可达的已提交历史；压缩包附带交接文档和 SHA-256 校验。
- 导出前要求工作区干净，避免未提交文件被遗漏却误认为已备份；被忽略的文件仍不包含在内。
- 导出不会自动上传或发送邮件。只有下载到独立位置，才构成额外的存储副本。
- Git 历史可能包含过去已提交的数据；`.gitignore` 不能清除历史中的秘密。

## 当前应用沿用的结构

- 单文件 HTML/CSS/JavaScript，无构建工具和应用依赖；Python 静态服务器仅供开发预览。
- 待办保存在浏览器 localStorage，不跨设备同步。代码备份不能替代待办数据导出。
- 本轮只建立开发记录和备份流程，不改变应用行为，也不引入账号或后端服务。
